The three that mattered

Everything else was refinement. These were defects a buyer would have hit, and two of them lied to the buyer rather than merely inconveniencing them.

The verdict badge could fabricate a verdict Trust
The project verdict chip was keyed on a coloured emoji the model was asked to prefix its header with, read as headerLine[0], defaulting to CONSIDER when that character was anything else. The verdict word was already sitting beside it in bold. So the moment the editorial no-emoji rule landed, every project in every response would have rendered as CONSIDER — a verdict the advisor never gave, shown with full confidence. Found while removing emoji; the cleanup was worth less than what it surfaced.
Compound questions lost half the answer Trust
“Does it have a pool, and what is its RERA number?” returned a complete, correct amenities answer and said nothing at all about RERA. The amenity branch matched first, wrote its response and returned. The buyer is left to conclude we hold no RERA data for a project whose RERA number was in the row we had just read.
No topic handler ever emitted a project card Dead end
All twelve of them answered and ended the response without a single card. Every drilldown — possession, payment plan, amenities, connectivity — produced a good answer about a project the buyer then had no way to save, open or compare. The only way to summon a card was to re-ask the same question in listing phrasing.

The slot was capped at 56px with overflow-hidden — room for two rows and nothing else, so “+X more configurations available” rendered and was then cut off by the very container meant to keep cards tidy.
Mobile: one drawer, a rail that scrolls, targets you can hitUX
Two results drawers with one broken; pills stacked vertically by flex-wrap; 28px touch targets against a 44px minimum; and touch-pan-x on tables, which was the scroll trap rather than a fix for it.
Twelve topic handlers extractedStructure
Every fabrication found this session lived in one 4,400-line file. chat-router.ts is now 3,834 lines with a thirteen-file handler registry beside it.
Coverage proven, not assertedTest
A test walks all 119 scalar fields and 20 relations and fails by name if any exposed column never reaches the prompt. Expose a column without projecting it and chat quietly cannot answer about it — that case is now caught.

The road to ninety

In dependency order — step one gates everything visual, and step two is a billing switch rather than an engineering problem.

  1. Browser QA pass
    Still the largest risk on the board, and now larger: the filter dock moved below the input, its pills wrap instead of scrolling, the chat stream is driven through an extracted reducer, and the detail panel's tabs became a real tablist. All of it typechecks, passes 1,667 tests and builds — none of it has been clicked. Nothing here should ship to a buyer before someone opens it on a phone.
    blocking · ~1h · confirms the last four commits
  2. Enable Gemini billing
    Unchanged and still free: explicit caching is implemented, tested and wired, and returned limit=0 because cache storage is unavailable on the free tier. Nothing to build.
    no code · ~60% input cost · +1
  3. Tool access on the fallback legs
    Mistral, Cerebras and Groq all carry supportsTools: false. When Gemini rate-limits, web_search, area_info, rera_check and commute silently vanish for that turn — the prompt correctly switches to its no-lookups variant, so nothing is fabricated, but the advisor quietly gets less capable and nothing surfaces it. Three of five legs are blind. SERPER_API_KEY is also empty, so Tavily has no fallback. Both are cost decisions rather than engineering ones.
    a decision, not a task
  4. Label the corridor's far end
    Sectors 151 and 152 sit past the last sector tagged micro_market = 'Noida Expressway', so the axis stops short of them. This is the design working as intended: tag them in SectorIntelligence and the corridor extends itself. Every attempt to reach them geometrically pulled old Noida in first.
    data, not code · two rows
  5. Extract the shared project pipeline
    The last structural item in chat-router.ts. The tool handlers are out; the pipeline every response path shares is not. Worth doing when someone can verify a turn end to end, not overnight.
    ~4h · unblocks the last two handlers
The remaining 10% is not a feature. It is verification. Almost everything on this list is “prove it works” rather than “build it”, which is the right shape for a product whose entire differentiator is that its data can be trusted.

The overnight pass

Six commits against the four components rated below seven, plus the defect that started it. Everything below is verified by tests, a typecheck and a clean production build — and by nothing a human has looked at.

A corridor asked which of its own sectors you meant Dead end
Two defects stacked. SECTOR_CORRIDOR_ALIASES mapped "Noida Expressway" to four sectors while two other files documented it as 128–158 and the database put fifteen on it. Then the sector-disambiguation guard saw four distinct sectors, discarded every result and asked "did you mean 107, 137, 143 or 150?" — the corridor's own contents, returned as a question. Every answer re-entered the same state. The corridor could not produce a card at all, in any phrasing.
Location now resolves from the database Adaptive
No list survives. A phrase resolves through tiers that each read live data: an exact sector, a numeric band ("132 to 150"), SectorIntelligence.micro_market, and geometric expansion along the axis through the sectors an analyst has labelled. That last tier is the point — label three sectors and the geometry finds the rest, including inventory added next month that nobody thought to tag. A corridor is a line, not a disc: a radius around the seeds put Central Noida inside the Expressway when measured, so membership is perpendicular distance to the axis at a 2km half-width. Verified against live rows: 15 sectors, 76 projects, no cross-city bleed.
The filter dock read INTENT_PATCH back to the buyer Trust
Changing the sector from 75 to 79 put the literal string "INTENT_PATCH" in the transcript as the buyer's own turn, and handed the model [User selected UI option: updated search] — no field, no value. It answered about the old sector, confidently. Both halves now carry the sentence the buyer actually chose. Found alongside: clearing a budget fired two dispatches, and the second lost to the submit lock.
Dialogs a keyboard could open and not leave Access
Worse than the "untested" the last audit claimed. Tab walked straight out of the compare sheet into the chat behind the backdrop, where the focus ring is invisible and the buyer is typing into a form they cannot see. Escape did nothing. Closing dropped focus on <body>. One hook now traps, closes and restores across three dialogs. The detail panel's six tabs were six loose buttons — a screen reader announced "Overview, button" with no hint it was one of six; they are now a tablist with a roving tabindex and arrow keys.
Untestable logic, made testable Structure
Two hundred lines of stream message shaping and three restore decisions lived inside effects inside a 2,089-line component, reachable only by running a chat turn. Both are pure and now sit in lib/chat/ under 49 tests — including that a gathering turn never shows a property spinner, that a question sorts above the answer written in the same millisecond, and that responseMode comes from the backend rather than from what the frontend can see. Three hundred lines of tool dispatch left the request handler the same way.
Connectivity distances are synthetic Data
Worth knowing before anyone builds on them: 280 identical "Noida - Greater Noida Expressway" rows from the enrichment script, and at a 3km threshold they return Sector 62 and Greater Noida West. They were the obvious source for deriving a corridor and they are unusable. lat/lng is the only trustworthy geo signal — 280 of 280 populated, 253 distinct.
The honest limit. Every claim above rests on tests, a typecheck and a build. The chat was never opened, no turn was streamed from a live provider, and no phone was held. A green suite proves the shaping is right; it cannot prove the dock is reachable with a thumb.

Corrections

Things I got wrong earlier in this session, stated plainly so the numbers above can be trusted.

Admin analytics were never missing empty states
I rated them 5/10 on a bad grep — I searched for length === 0 where the code uses length > 0 ? … : …. All four pages have proper empty states with icons and copy. Corrected to 7, and I stopped before “fixing” something that was not broken.
A code comment shipped into the chat
Removing the hardcoded chip grid left its explanation as bare // lines in a JSX children position, which React renders as literal text. The paragraph appeared in the chat above the results header. My first rewrite reintroduced the same bug by quoting the comment delimiters inside the comment.
A parallel edit was swept into my commit
A git add -A during the handler extraction pulled in frontend work being done at the same time, under a message about handler extraction. Nothing was lost and it has since been reverted, but I should have staged my own paths.
Relation gating saves round-trips, not tokens
Measured after the change: prompt tokens were unchanged at 5,204, because the facts block was already gated. The win is database and wire, not spend. The audit predicted this; the measurement confirmed it.

On the skills libraries

I scanned 1,983 skills across both folders and adopted none of them. The candidates that matched our stack were generic community boilerplate — the cost-optimisation skill is AWS cloud spend, the LLM-patterns skill is Dify RAG chunking, and markstream-react is a beta dependency that would replace markdown rendering we already do well.

The one genuinely strong idea in the external audit I was given — prompt caching — I got further with by measuring our actual prompt than any skill would have provided. Of that audit's seven claims, two held up: the composite index it said was missing has existed all along, and the mobile table fix it proposed had already shipped.

That is a scan-and-reject, not an exhaustive review of all 1,983. If a systematic pass is wanted, it deserves to be scoped as its own task rather than folded in.
