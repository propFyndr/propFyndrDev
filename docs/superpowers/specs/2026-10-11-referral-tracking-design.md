# Referral Link Tracking — Design

**Date:** 2026-10-11 · **Status:** approved in brainstorming, awaiting spec review · **Audience:** the three founders (SUPER_ADMIN)

## Goal

Measure whether RealtyAsk spreads on its own. A super admin generates a labelled link, sends it to one person, and watches the chain: who arrived through whom, on which device and app, what each person asked, and whether they activated. This is product validation, not marketing attribution.

## Non-goals

- No collection of real names. The admin names the link ("Rahul – college"); visitors are never asked who they are.
- No device fingerprinting.
- No expiry. Revoke replaces it.
- No visibility for SALES, ANALYST, BUILDER or PARTNER.
- No new chart or graph dependency.

## Decisions (from brainstorming)

| Topic | Decision |
|---|---|
| Storage | Two new tables (Option A). Rejected: rebuilding from analytics events (slow, fragile, no home for labels/revoke); columns on `ChatSession` (a session is not a device or a person) |
| Landing | Chat (`/discover`) with a one-line greeting |
| Child shares | Address-bar code + new chat share button + existing dossier and shortlist shares |
| Notice | Small dismissible text, cookie-banner style, auto-hides |
| Retention | 12 months for guest chats and referral data; purge job makes the policy true |
| Labels | Admin-chosen, admin-only, root links only |

## Core rule

One link per person. The only thread connecting devices is the code in the URL, so the design keeps that code in every URL a person can copy or share.

- First real device to open a labelled root link = the labelled person (the **holder**).
- Every later new device on that root link came through the holder: attributed to the holder's subtree, `depth_inferred = true`.
- A device's parent is set once, on first arrival, and never changes (first touch wins; cycles impossible).
- Every device gets its own personal code, including organic visitors with no link. Organic sharing forms its own trees.

## Data model

```prisma
enum ReferralLinkKind {
  ROOT      // generated by a super admin
  PERSONAL  // owned by one device
}

model ReferralLink {
  code                String           @id   // 8 chars, crypto-random, Crockford base32
  kind                ReferralLinkKind
  created_by_admin_id String?                // ROOT only
  label               String?                // ROOT only, admin-only, <= 60 chars
  note                String?                // ROOT only, admin-only
  greeting_name       String?                // ROOT only, e.g. "Furqan"; shown to the visitor
  holder_guest_token  String?                // ROOT only: first real device to open it
  owner_guest_token   String?  @unique       // PERSONAL only
  revoked_at          DateTime?
  created_at          DateTime @default(now())

  @@index([created_by_admin_id])
  @@map("referral_links")
}

model ReferralVisit {
  guest_token        String   @id            // one row per device
  user_id            String?                 // set on sign-in (migrateSessions)
  own_code           String   @unique        // this device's PERSONAL link
  arrived_via_code   String?                 // code in the URL on first arrival; null = organic
  root_code          String                  // tree key: the ROOT code, or own_code for an organic origin
  parent_guest_token String?                 // resolved parent device; null for holders and organic origins
  generation         Int                     // 0 organic origin, 1 holder, parent + 1 below
  depth_inferred     Boolean  @default(false)
  prior_user         Boolean  @default(false) // had chats before arriving via a link
  device_class       String                  // mobile | desktop | tablet
  os                 String                  // ios | android | windows | macos | other
  app_guess          String                  // instagram | facebook | unknown (in-app browser UA)
  share_channel      String?                 // wa | sms | copy | native | dossier | shortlist | link
  first_seen_at      DateTime @default(now())

  @@index([root_code])
  @@index([parent_guest_token])
  @@index([arrived_via_code, first_seen_at])
  @@map("referral_visits")
}
```

Stored: derived device fields only. **Not stored:** raw user-agent, IP address.

Migration is additive (two tables, one enum). It is run only after explicit confirmation.

## Arrival flow

1. Admin generates a root link in `/admin/referrals`: `propfyndr.com/r/k9x2`.
2. `frontend/app/r/[code]/page.tsx` renders static OpenGraph metadata (generic RealtyAsk card, no DB call) and a tiny client component that does `router.replace('/discover?r=k9x2')`. Preview bots read the card and never run the redirect.
3. A client hook `useReferral`, mounted in the root layout and skipped on `/admin`, `/portal`, `/builder` and `/partner`:
   - If localStorage already holds this device's own code: no network call. It rewrites the address bar if `?r=` is present.
   - Otherwise it calls `POST /api/v1/referral/arrive` with `{ code?, guestToken, channel? }`, caches the returned `ownCode`, and shows the greeting if one is returned.
   - Address bar: `history.replaceState` to the same path with `?r=<ownCode>` (and `c` removed).
4. Server `arrive`:
   - Known preview-bot UA: `204`, no row.
   - Rate limit: 20 per 10 minutes per guest token and per IP (`checkRateLimit`).
   - Visit already exists for this guest token: return its `own_code`, change nothing.
   - Guest token has earlier `ChatSession` rows: organic, `prior_user = true`, `arrived_via_code` logged, no parent.
   - Code missing, unknown or revoked: organic origin (`generation 0`, `root_code = own_code`).
   - ROOT code with no holder: this device becomes holder (`generation 1`). Set `holder_guest_token`.
   - ROOT code with a holder: `parent = holder`, `generation 2`, `depth_inferred = true`.
   - PERSONAL code: `parent = owner`, `generation = parent + 1`, `root_code = parent.root_code`.
   - In the same transaction: create the device's PERSONAL `ReferralLink` and the `ReferralVisit`.
   - Response: `{ ownCode, greeting: { name } | null }`. The name is the root's `greeting_name` only for the holder and inferred-downstream arrivals on a root link. Personal-code arrivals get a generic greeting.
5. Greeting: a one-line note above the chat input, not an AI message (0 tokens). "Furqan thought you'd find this useful." / "A friend shared RealtyAsk with you." Shown once.

## Sharing surfaces

All three append `?r=<ownCode>&c=<channel>`:

- **New "Share RealtyAsk" button** in the chat UI. It uses `navigator.share` where available (`c=native`); otherwise a menu with WhatsApp (`wa.me/?text=`, `c=wa`), SMS (`sms:?&body=`, `c=sms`) and Copy (`c=copy`).
- **Dossier share URL** (`/dossier/:token`, `c=dossier`).
- **Shortlist share URL** (`/s/:id`, `c=shortlist`).

Address-bar copies carry `r` only. That arrival records `share_channel = link`.

## Identity merge

- **Sign-in:** the existing `migrateSessions` flow also sets `ReferralVisit.user_id` for that guest token.
- **Two devices, one person:** when two visits share a callback phone number, the admin drawer shows "possibly the same person as <node>". The phone itself is not shown there; it stays in the audited lead detail. Nothing is merged automatically.

## Admin — `/admin/referrals` (SUPER_ADMIN only)

**Policy:** add `/^\/referrals\b/` to the read and write denials for SALES, ANALYST, BUILDER and PARTNER in `backend/src/lib/adminPolicy.ts`. Add `/^\/referrals\/nodes\/([^/]+)$/` to `AUDITED_READS` in `backend/src/lib/adminReadAudit.ts` (entity `referral_node`), because the drawer describes one person.

**Endpoints** (admin router):

| Method & path | Purpose |
|---|---|
| `POST /referrals` | `{ label, note?, greetingName }` creates a ROOT link |
| `GET /referrals?scope=mine\|all` | Root links with stats |
| `GET /referrals/:code/tree` | Nodes for one tree (root or organic) |
| `GET /referrals/nodes/:guestToken` | Person drawer (audited) |
| `POST /referrals/:code/revoke` | Stop new attribution; the tree is kept |
| `POST /referrals/:code/reset-holder` | Clear holder (for when an admin opened their own link) |
| `GET /referrals/metrics` | Cross-link metrics |

**UI:**

- **Generate:** label (required, 60 characters), From name, optional note. Output: link with Copy, WhatsApp and **Preview** buttons. Preview opens `?r=<code>&preview=1`, which the arrive endpoint ignores.
- **Links list:** label, created by, date, devices reached, deepest generation, activated, last activity, Revoke. "Mine / All" filter.
- **Tree:** indented list. Each row shows label or guest id, generation, device, app or channel, message count, saved, callback. Inferred rows are labelled "via <holder> (exact sender unknown)". Organic trees are listed separately under "Organic".
- **Drawer:** summary from `ChatSession.summary_location`, `summary_financial` and `summary_timeline` (0 tokens); actions (saves, compares, dossier made or shared, callback, site visit, "gave phone"); chats with message counts; "Open transcript" goes to the existing audited `/admin/conversations/:id`.

**Metrics** (computed on read; materialise only if slow):

- Devices per generation.
- **Activated** = ≥3 user messages, OR any save, callback, site visit or dossier, OR a return visit ≥24h after first arrival.
- Activation rate per generation.
- **K per generation** = activated children / activated parents.
- Median time from arrival to first child arrival.
- Channel and app breakdown.
- **Broadcast alert:** ≥25 new visits on one `arrived_via_code` within any 1-hour window.

## Notice

Small text strip at the bottom of the chat, cookie-banner style, shown to every visitor:

> Chats are stored and may be reviewed by the RealtyAsk team to improve answers. [Privacy policy] ×

- Hides on ×, on first message sent, or after 10 seconds, whichever comes first. Never shown again (localStorage flag, in try/catch).

## Privacy policy updates (`frontend/app/privacy/page.tsx`)

- **§1 Information We Collect:** add "Shared-link data": the link a visitor arrived through, the link they share, device type, an in-app-browser guess, timestamps. Remove "device fingerprints" if implementation confirms nothing collects them.
- **§5 AI Conversational Engine:** replace "for your personal review" with: transcripts may be reviewed by the RealtyAsk founding team to improve answers and understand how the service is used.
- **§6 Purpose:** add "understanding how RealtyAsk is shared and improving answers".
- **New section, "Shared Links":** how codes work; only RealtyAsk founders see referral data; no names are collected from visitors; it is never shared with builders or partners.
- **§10 Cookies & Local Storage:** add the device referral code and the notice-dismissed flag.
- **§12 Retention:** guest chat transcripts and referral data are kept for 12 months, then deleted.
- `lastUpdated`.

## Retention purge

Script `npm run purge:retention`, **dry-run by default** (prints counts). `--apply` deletes:

- `ChatSession` rows with `user_id IS NULL` and `last_active` older than 12 months (messages cascade as today).
- `ReferralVisit` rows with `first_seen_at` older than 12 months, and their PERSONAL `ReferralLink`.

The first `--apply` run needs explicit confirmation (irreversible). Scheduling it is a follow-up once the dry-run numbers look right.

## Edge cases

| Case | Handling |
|---|---|
| Admin opens own link | Preview button; Reset holder action |
| Existing user opens a link | Organic, `prior_user = true`; not counted as growth |
| Device arrives on a second code | Ignored (first touch) |
| Incognito, cleared storage, in-app browser vs Chrome | New device node; phone/sign-in signals shown, never auto-merged |
| Revoked code | Normal landing, no greeting, organic |
| Visitor with no link | Organic origin with own code |
| Scripted fake arrivals | Random 8-character codes, rate limit, broadcast alert |
| Preview bots | Arrival needs JS; known bot UAs return 204 |
| Chat deleted | Node stays as "deleted": no summary, no transcript; counts intact |
| localStorage throws | Hook calls arrive every page load; the server's first-touch rule keeps it idempotent |

## Testing

**Backend** (`npx tsx --test`):
- Attribution as a pure function: holder, inferred downstream, personal chain, first touch, revoked, unknown code, prior user, own-code no-op.
- Activation and K maths on fixtures.
- Policy: SALES, ANALYST, BUILDER and PARTNER get 403 on every `/referrals` path.
- `isAuditedRead('GET', '/referrals/nodes/x')` is true.
- Arrive rate limit; bot UA returns 204.
- Code generator: alphabet and length.

**Frontend** (`npx jest`):
- The hook rewrites the address bar to the own code.
- Share button, dossier and shortlist URLs carry `r` and `c`.
- Notice hides on ×, first message, and timeout.

**Manual, two real phones:** WhatsApp forward, iMessage, open from Instagram. Check the preview card, node count, depth labels and app guess.
