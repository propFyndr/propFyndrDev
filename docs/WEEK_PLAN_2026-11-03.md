## Day 1: "What could go wrong?" answered from official records

**Why today.** On "is Mezzaria the safer buy", ChatGPT and Perplexity cite 53 UP-RERA complaints and a lapsed registration. We hold neither, and our answer called its record "unblemished".

1. [ ] **Collect UP-RERA complaints, orders and abeyance lists** for every project we can match. They are saved as pending rows that a person approves, not written straight in.
2. [ ] **Show each new fact with its source and date.** No date, no show. **(Furqan)** decides how complaint counts are worded.
3. [ ] **Give any project a "what could go wrong" box.** Lapsed registration, complaints, delays, missing occupancy certificate, lawsuits. Each line comes from a record, or says "not on record".
4. [ ] **Block false reassurance in code.** No "clean", "safe" or "Delivered" label without a record behind it. Tests are written first, from the 31 Oct answers.
5. [ ] **Re-run 40 safety questions before and after.** Re-score the Mezzaria answer against ChatGPT and Perplexity.

## Day 2: Run the site safely

**Why today.** Four months in, one bad push can still reach the live server, and a database mistake older than 6 hours cannot be undone.

1. [ ] **Stop broken code reaching buyers.** Every release is checked first. A version that fails to build or start is blocked, or rolled back automatically. **(Furqan)** approves the Render and GitHub settings.
2. [ ] **Make test results trustworthy.** Tests run on the same setup as the live server, and all 225 scripted chats give identical results three runs in a row.
3. [ ] **Prove we can get the data back.** A daily copy of the live database is kept somewhere else, and we restore it once to show it works.
4. [ ] **Hear about outages first.** The team's phones get a message within five minutes when the site, the chat or sign-in stops working.
5. [ ] **Know what runs out first.** One page shows how full each free plan is (hosting, database, login, cache) and the date each one hits its limit.

## Day 3: Sign-in always works

**Why today.** On 29 Oct nobody could sign in or sign up on live, because the login provider's monthly allowance ran out.

1. [ ] **Get sign-in working on live and prove it on a phone.** A new person signs up, signs out, signs in and saves a project, recorded on screen. **(Furqan)** decides the Supabase plan.
2. [ ] **Find what used up the allowance.** Split the last 30 days into file downloads, logins and our server's checks, then cut the biggest cause.
3. [ ] **Test sign-up every hour, automatically.** A throwaway account is created and removed on live; the team gets a message after two failures in a row.
4. [ ] **Write the one-page choice.** Stay on Supabase, move login to Neon, or run both, with the screens each choice touches. **(Furqan)** picks; nothing moves before that.
5. [ ] **Set the sign-up rules and delete the junk accounts.** About 23 of 34 are test emails. **(Furqan)** approves the list before anything is deleted.

## Day 4: Disputed facts checked against the official register

**Why today.** Five conflicts were found on 31 Oct and more sit in `MEMORY.md`. One wrong number loses a buyer for good.

1. [ ] **Settle the five known conflicts.** Astralis registration, Mezzaria's rate and metro distance, Eureka Park, the duplicate Meadow row. Each gets our value, the official value, a source and a date.
2. [ ] **Untangle registration numbers.** 16 are shared by different projects, 57 are malformed, 4 same-name pairs differ. Resolve each from UP-RERA or hide it. Never guess.
3. [ ] **Sort the suspicious defaults.** 18 "delivered" projects with no certificate, 226 clear-title rows, 39 zero-delay builders, 80 placeholder map points, one unit mix-up. Each gets a rule and a decision.
4. [ ] **Try every fix on dev first, with a backup.** Live changes happen only after **(Furqan)** says yes in the same message.
5. [ ] **Make the checks permanent and decide what "draft" means.** All 382 live projects are draft and the label hides nothing. **(Furqan)** decides what it should do.

## Day 5: Where the ten seconds go

**Why today.** First word took 6 seconds before our 31 Oct changes and 10 seconds after. Nobody has measured why. The target is 3.

1. [ ] **Time each step of one answer.** Routing, understanding, data, prompt, AI wait, first word, shown as one chart.
2. [ ] **Measure 100 questions on dev and live.** Median, slowest and worst time for every step.
3. [ ] **Name the step that cost four seconds.** If we cannot tell, the report says so and why.
4. [ ] **Cut the three slowest steps.** **(Furqan)** first decides the paid Gemini key and the provider order, which change what is possible.
5. [ ] **Re-run the same 100.** Median at least 30% faster, and no new failure in the 60-question test.

## Day 6: What we store about buyers

**Why today.** Passwords were committed to git on 2 Oct. PostHog was sent buyers' chat text word for word. Nothing stops a script flooding a builder with fake callbacks.

1. [ ] **Account for every leaked password and key.** Check each with its provider and get each one changed. **(Furqan)** changes them.
2. [ ] **See what PostHog and Langfuse really receive.** Record a real session, remove chat text and phone numbers, and add a test that fails if they come back.
3. [ ] **Stop fake callback floods.** A light check on guest callback and site-visit forms; a script of 200 requests is blocked and a real guest still finishes within a minute.
4. [ ] **Write the data rules and build delete and export.** What we keep, for how long, who sees it, and a one-step delete of a buyer's chats and leads. **(Furqan)** approves retention.
5. [ ] **Fix the 31 security warnings in backend software.** Critical one first. Any left unfixed gets a written reason.

## Day 7: The front door, the re-score, the close

**Why today.** The landing page changed three times in three weeks on taste. We have visitor numbers to decide with.

1. [ ] **Compare the two landing pages with real numbers.** How many visitors send a first message, and how many save or ask for a callback. Real people only; too-small periods are marked as such.
2. [ ] **Tag which landing page each visitor saw.** The next comparison then does not depend on dates.
3. [ ] **Decide and clean up.** Keep dark, bring the revamp back, or keep both. **(Furqan)** decides; then remove what is left over, in the how-it-works page, sign-in styling and sitemap.
4. [ ] **Re-score the 43-question comparison.** Same questions as 31 Oct, before and after per question next to ChatGPT and Perplexity, worst changes first.
5. [ ] **Write the cycle report and the next cycle's first five tasks.** One page: done, not done with reasons, numbers against `C1_BASELINE.md`.
